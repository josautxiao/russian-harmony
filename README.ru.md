## О проекте

«Русская гармония» — структурированный набор инструкций и справочных материалов для ИИ-ассистентов, поддерживающих формат `SKILL.md`. Он объединяет понятия, приёмы голосоведения, функциональные трактовки, каденции и модуляционную технику из двух учебников, сохраняя различия между ними и ссылки на источники.

Материалы предназначены для учёбы, подготовки занятий, разбора задач и создания собственных гармонизаций. Законченное четырёхголосие необходимо проверять по конкретным звукам, октавам, ритму и контексту. Это не отдельная программа, не система автоматического распознавания нот, не полный перевод учебников и не сборник готовых решений.

**Языки:** описания README полностью представлены на китайском, английском и русском. Инструкции навыка, конспекты тем и большинство справочных файлов сейчас написаны преимущественно по-китайски с сохранением важных русских терминов. Наличие трёх README не означает полного перевода всех материалов на три языка.

## Принципы

- **Единый порядок обучения:** введение и 41 тема учебника Е. Н. Абызовой.
- **Объединение общего с сохранением различий:** все 60 тем коллективного учебника сопоставлены основной последовательности; самостоятельные дополнения выделены отдельно.
- **Проверяемые источники:** указываются учебник, тема, печатные страницы и положение в использованных сканах.
- **Сначала замысел, затем изложение:** структура фразы, каденции, тональные цели и голосоведение предшествуют выбору конкретного расположения.
- **Разные уровни требований:** технические нормы, требования педагога, стиль и эстетические предпочтения не смешиваются.
- **Загрузка по необходимости:** основной файл направляет ассистента к нужной теме, а не требует чтения всей базы при каждом вопросе.

## Источники и структура

| Обозначение | Учебник | Роль в этой версии |
|---|---|---|
| A | Е. Н. Абызова. *Гармония*. Москва: Музыка,2008 | Основная последовательность: введение и 41 тема |
| B | И. И. Дубовский, С. В. Евсеев, И. В. Способин, В. В. Соколов. *Учебник гармонии*. Москва: Музыка,1965 | Сопоставление, дополнения и сравнение 60 тем |

Учебник B написан четырьмя соавторами и не приписывается одному И. В. Способину. Годы указаны по внутренним выходным данным использованных сканов. В других изданиях и сканах смещение между печатной страницей и страницей PDF может отличаться.

Охвачены главные и побочные аккорды, обращения, септаккорды и нонаккорды, каденции, неаккордовые звуки, диатоника и лады в русской музыке, альтерация, отклонения, модуляции, органный пункт и мажоро-минор. Обзор гармонии XX века из учебника A сохранён отдельно. Тональный план, систематический гармонический анализ и методика развёрнутых задач из B представлены в дополнениях.

См. [полное соответствие тем](references/source-map.md) и [индекс JSON](references/source-index.json). Для каждой темы создан вход в материал, но все нотные примеры, задания и редкие варианты не воспроизводятся.

## Различия между учебниками

Системы не полностью совпадают. В частности, сохранены разные трактовки III и VI ступеней, ограниченное исключение для октав в заключительном разрешении неполного доминантсептаккорда, употребление названий хроматической и модулирующей секвенций, а также трёх- и четырёхступенная классификация родства тональностей.

Если источник не задан, навык следует последовательности A и более осторожным нормам начальных письменных задач. Указание на B или требования конкретного педагога явно меняет этот выбор. См. [таблицу различий](references/differences.md).

## Установка

### Без программирования

1. На странице репозитория нажмите **Code → Download ZIP** и распакуйте архив.
2. Назовите полную папку `russian-harmony`. Непосредственно внутри должны находиться `SKILL.md`, `chapters/` и `references/`.
3. Поместите всю папку в каталог навыков вашего ИИ-приложения. Одного файла `SKILL.md` недостаточно.
4. Проверьте список навыков. При необходимости откройте новый сеанс или перезапустите приложение.

| Приложение | Обычный личный каталог | Явный вызов |
|---|---|---|
| Codex | `~/.agents/skills/russian-harmony/` | `$russian-harmony` |
| Claude Code | `~/.claude/skills/russian-harmony/` | `/russian-harmony` |

`~` означает домашний каталог пользователя. Для проекта в Codex также можно использовать `.agents/skills/russian-harmony/`. Другие приложения могут поддерживать формат Agent Skills; руководствуйтесь их документацией. Работа в каждом таком приложении отдельно не проверялась. При наличии одноимённой папки сначала сохраните или сравните свои изменения.

### Через Git

Склонируйте весь репозиторий в личный каталог навыков Codex:

```bash
git clone https://github.com/josautxiao/russian-harmony.git ~/.agents/skills/russian-harmony
```

Для Claude Code замените каталог назначения на `~/.claude/skills/russian-harmony`. Обычная работа с конспектами не требует запуска OCR, установки сторонних пакетов Python или исходного конвертера. Для разбора конкретных нотных примеров и задач необходимо самостоятельно получить соответствующий учебник, которым вы вправе пользоваться.

Обычный чат может не поддерживать установку навыков. Загрузка файлов сама по себе не обеспечивает автоматическую доступность навыка в будущих беседах.

## Качество и ограничения

При подготовке первой версии текстовый OCR был выполнен для 824 изображений из двух сканов. Завершение обработки не означает точности транскрипции. Ноты, ритм, знаки альтерации, верхние/нижние индексы и цифровку нельзя надёжно восстановить только по обычному OCR.

- Условия задач, нотные примеры и спорные детали проверяются по оригинальным страницам.
- Римские цифры дают функциональный план; полное решение требует звуков, октав, длительностей и проверки голосоведения.
- Начальная версия прошла проверку структуры, ссылок, охвата тем, независимые пробы применения и проверку собственного примера SATB. Это не гарантирует безошибочности всех правил или будущих ответов.
- Автоматическая проверка репозитория оценивает структуру, ссылки на источники и состав публичных файлов, но не устанавливает музыкальную правильность или наличие юридических прав.

См. [требования к OCR и сверке](references/ocr-quality.md). Сообщения об ошибках с минимальным примером и точным источником приветствуются в Issues и Pull Requests.
